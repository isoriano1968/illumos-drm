# The display TUs of i915n (paths relative to drivers/gpu/drm/i915 of the
# pinned tree), added to tus.txt for the display build (drivers/i915/build.sh
# with DISPLAY=1, the default): the 145 display objects of Linux's i915.mod
# in the R5c configuration (artifacts/i915n-kms/display-tus.txt: display/*.o
# and the display glue i915_bo .. i915_panic) minus the families whose
# external dependencies have no illumos counterpart and which the admitted Gen6-Gen9.5 PCH GPUs
# do not need for unprotected display (DSI/LPE are on excluded SoCs;
# HDCP is unavailable, including where the hardware supports it); illumos/i915_excluded.c (generated by
# illumos/gen-nodisplay.py --excluded, which gives each stub's reason)
# replaces them (design note notes/i915n-kms-design.md, section 3):
#   DSI (MIPI DSI bus): display/icl_dsi.c, display/vlv_dsi.c,
#     display/vlv_dsi_pll.c, display/intel_dsi.c, display/intel_dsi_vbt.c,
#     display/intel_dsi_dcs_backlight.c
#   HDCP (MEI/GSC firmware interface, GPL drm_hdcp_helper):
#     display/intel_hdcp.c, display/intel_hdcp_gsc_message.c,
#     display/intel_dp_hdcp.c, i915_hdcp_gsc.c
#   LPE audio (platform devices, IRQ chips): display/intel_lpe_audio.c
#   the panic screen: i915_panic.c (drm_panic is not carried, patch 0002
#     leaves its helpers out; i915_excluded.c has the interface, whose
#     alloc must succeed for every framebuffer)
# and the tracepoint TU display/intel_display_trace.c (GPL-2.0; it only
# defines the display tracepoints, which illumos does not have, as R5c's
# two headless tracepoint TUs; fetch-and-patch.sh replaces
# intel_display_trace.h by a generated MIT no-op header).
#
# A line "-<TU>" takes a TU of tus.txt out of the display build: the
# headless stubs of the display (i915_nodisplay.c) and of the KMS helpers
# (i915_nokms.c, which misc/drm_kms provides).
#
# 132 Linux TUs and 2 illumos sources.
